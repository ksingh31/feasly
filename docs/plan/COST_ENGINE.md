# Feasly — Cost Engine Spec

**Package:** `packages/cost-engine` — pure TypeScript, zero I/O, deterministic.
Same function runs in Azure Functions (web + API) and is wrapped by the MCP
server. Unit tests pin every formula and range.

**Golden rule:** every dollar figure on screen comes from this engine.
The LLM may only write narrative from the engine's outputs and **must not
invent, adjust, or rephrase any number**.

## Versioning

- All parameters live in `cost_data_versions` (see SCHEMA.md); the engine takes
  `(inputs, costParams)` and returns ranges. `build`, `land`, `reno` $/sqft and
  margins are **server-side secrets** — never serialized to the client.
- Prototype figures ($285/$365/$480 per sqft, quadrant land $/sqft, ±8/±10%)
  are **placeholders** until calibrated from Karan's cost Sheet (blocked item 3).
  Ship order: calibrate → freeze `2026-XX-v1` → M1 walks the skeleton on real params.

## New build

Inputs: `{ address_key, sqft, tier: 'standard'|'premium'|'luxury', lot_sqft?, quadrant? }`

1. **Land** — preferred: City-assessed total value for the address
   (data.calgary.ca `4bsw-nn7w`, field: assessed value). Label in UI:
   *"Land (property acquisition — City-assessed basis)"*.
   - `land = assessed_value × { low: 0.90, high: 1.10 }`
   - Fallback (no assessment match): `lot_sqft × neighbourhood avg $/sqft`
     from `land` params → same ±10% band, flagged `land_source: 'estimate'`.
2. **Build** — `build = sqft × tier.per_sqft` → band `× { low: 0.92, high: 1.08 }`.
3. **Total** — `total.low = land.low + build.low`, `total.high = land.high + build.high`.
4. Round all bands to the nearest $1,000 (`fmtMoney`).
5. Output rows: Land, Build, Total (+ per-project rows in comparison).

Accuracy target: **±15%** vs. eventual builder quotes — tracked in M6; never
presented to the user as a guarantee.

## Renovation

Inputs: `{ reno_type, sqft, tier?, underpinning?: bool, quality?: 'standard'|'premium' }`

- `extensive`: `sqft × reno.extensive.per_sqft[tier]` (proto placeholder $165–$310)
- `addition`: `min(sqft, 400) × reno.addition.per_sqft[tier]` (placeholder $300–$420)
- `basement`: `sqft × reno.basement.per_sqft[tier]` (placeholder $85–$175)
  + underpinning: `reno.underpinning.{low,high}` (placeholder $35k–$80k)
- `combined`: sum of applicable components.
- Band: **±20–25%** (wider — existing-condition risk). UI notes: permits extra,
  scope discovery risk, structural complexity (carried from prototype copy).

## Comparison

Inputs: `{ neighbourhoods: [2–3], sqft, tier }`

Per neighbourhood: `land = avg_lot_sqft × avg_land_per_sqft → ±10%`;
`build` from tier params; `total` summed. Output marks `lowest_land: true` on the
cheapest. Same gating as new build (land visible, build/total blurred pre-gate).

## API contract (engine in / engine out)

```ts
interface EstimateInput {
  project_type: 'new_build' | 'renovation' | 'comparison';
  city: string;                       // 'calgary'
  sqft: number;
  tier?: 'standard' | 'premium' | 'luxury';
  address_key?: string;               // new_build
  reno?: { type: string; underpinning?: boolean };  // renovation
  neighbourhoods?: string[];          // comparison
}
interface MoneyRange { low: number; high: number }
interface EstimateOutput {
  rows: { label: string; range: MoneyRange }[];
  total: MoneyRange;
  assumptions: string[];              // e.g. "Land from City-assessed value $729,000"
  cost_data_version: string;
  land_source: 'assessed' | 'estimate';
}
```

`assumptions` is the **only** channel from engine → AI narrative: the LLM may
restate assumptions verbatim but may not add new ones.

## Narrative constraints (for the Meta-API prompt, M1)

- Input: the JSON above + community/zoning facts from the City API.
- Output: executive summary (2–3 sentences), 3–5 risk factors, neighbourhood
  context — plain language, no numbers beyond what the engine returned.
- Required footer, verbatim: *"Dollar figures are calculated deterministically
  from our cost model — not generated by AI."*
- Banned: sold prices, market-value claims, zoning/soil/utility assertions not
  present in City data, accuracy guarantees, compliance claims (PIPEDA etc.)
  until legally cleared.

## Test plan (ships with the package)

- Fixtures: 3 known addresses × 3 tiers → pinned ranges per `cost_data_version`.
- Property-based: `total.low ≤ total.high`, `total = land + build` componentwise,
  monotonic in sqft, tier ordering standard < premium < luxury.
- Secret-leak test: serialized API response contains no `per_sqft`, no margin,
  no param tables.
