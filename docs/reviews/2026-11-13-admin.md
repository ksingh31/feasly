# Feasly Admin Console: design review and redesign plan

Scope: 13 admin routes (login, leads, builders, users, disputes, billing, invoices + detail, calibration, sheets sync, estimates + detail, funnels, API keys). I reviewed all 256 screenshots in `audit/shots/admin/`, plus `report.json`, the admin source (`apps/web/src/app/features/admin/`), `docs/design-tokens.md` and `styles.scss`.
Screenshot names below are relative to `audit/shots/admin/`.

---

## Executive summary

1. **There is no admin design system.** Each of the 13 pages built its own shell, table, buttons, chips, modal and confirm. Admin SCSS adds up to 4,536 lines with 321 hex literals. `shared/components` has no modal, drawer, table, button or chip. As a result we see 4 page widths, 5 primary-button colours, 3 date formats, and several screens with unstyled native browser buttons.
2. **The overlays don't follow one model.** The "lead drawer" is really a centred modal. "Edit builder" is an inline form added below the fold. "Manage invoice" is a stack of 3 independent mini-forms with only a bottom Close button. Disputes open a panel under the table. API-key revoke uses a bare native-button dialog. Users' Deactivate has no confirmation at all.
3. **Navigation is a flat top bar of 11 equal links.** Records never link to each other: builder, lead, invoice and dispute IDs show up as plain text or raw UUIDs. An operator can't follow lead → builder → invoice → dispute without copy-pasting IDs. Two tools (Create invoice, Estimate lookup) even ask for a pasted UUID.
4. **Mobile is broken on 4 pages.** Builders renders 951px wide, Users 722px, Calibration 591px and API keys 474px. Modals get clipped. Table action columns (Manage, Mark as paid, Status) sit off-screen.
5. **Direction:** build a small admin kit first: AdminShell with a grouped left sidebar, PageHeader, DataTable + FilterBar, DetailDrawer, Modal, ConfirmDialog, StatusChip, EmptyState, KPI tile. Every record gets a URL-addressable right-side drawer with cross-links and one action footer. Then move each page onto the kit. Fix the bugs listed below first.

## Design findings

### Must-fix

**M1. Unify the overlay model.**
- Screens: leads drawer, builders edit, users edit, billing manage, disputes panel, API keys.
- Screenshots: `leads__desktop__loaded__lead-detail-drawer-viewport.png`, `builders__desktop__loaded__manage-builder-modal.png`, `users__desktop__loaded__edit-user-modal-viewport.png`, `billing__desktop__loaded__manage-in-review-modal-viewport.png`, `disputes__desktop__loaded__dispute-review-panel-viewport.png`, `api-keys__desktop__loaded__key-detail-viewport.png`.
- Problem: there are 6 different patterns.
  - The lead "drawer" is a 720px centred modal.
  - Builder edit is an inline card below the table, out of view when you click Edit, with no row highlight.
  - Dispute detail is a panel appended under the table.
  - API-key detail is a split pane.
  - Manage invoice and Edit user are modals with no close (X) and no header or footer.
- Recommendation: three overlay types only.
  - `AdminDetailDrawer` (right side, record view and edit). Use it for lead, builder, user, invoice-manage, dispute and API key.
  - `AdminModal` (centred, short create forms: invite user, add builder, issue key, create invoice).
  - `AdminConfirmDialog` (destructive or irreversible actions).
- Specs are in the component kit below.

**M2. Every destructive or irreversible action goes through `AdminConfirmDialog`, with the object named and the consequence spelled out.**
- Screens: users Deactivate, which has no confirm (B3). API-key revoke (`api-keys__desktop__loaded__key-revoke-confirm-viewport.png`: "Revoke this key? This cannot be undone." / native "Yes, continue"). Dunning retry (`billing__desktop__loaded__retry-charge-confirm-viewport.png`): the confirm swaps the buttons in place inside the table cell and the row grows. Dispute accept (`disputes__desktop__loaded__dispute-accept-confirm-viewport.png`): green "Confirm accept" for an action that voids and refunds the invoice.
- Recommendation: the title names the object ("Revoke 'Elite Craft website embed'?"). The body states the consequence ("Requests using fsk_live_7Hq2 will fail immediately"). Use a danger-variant primary button whose label repeats the verb ("Revoke key"), with Cancel focused by default. For the highest-risk actions (delete user, revoke a live key, accept a dispute on a paid invoice) add type-to-confirm. Deleting a user already has type-to-confirm; reuse it. Money actions (retry charge, mark paid, accept dispute) show the amount and the builder in the body.

**M3. Cross-link records and replace UUID entry with pickers.**
- Screenshots: `billing-invoice-detail__desktop__loaded.png` (References card shows builder/lead as plain text and three raw UUIDs), `disputes__desktop__loaded__dispute-review-panel-viewport.png` (invoice, lead and attribution UUIDs unlinked, title "Dispute d1500000-…"), `billing__desktop__loaded__create-invoice-form-viewport.png` ("Lead ID: UUID of the converted lead"), `estimates__desktop__loaded.png` (paste-a-UUID only), `api-keys__desktop__loaded__issue-key-form-viewport.png` (free-text "Tenant ID").
- Recommendation:
  - Add an `EntityLink` component (builder → `/admin/builders/:slug`, lead → `/admin/leads/:id`, invoice → `/admin/invoices/:number`, dispute → `/admin/disputes/:id`), each opening the record's drawer.
  - Show human identifiers (invoice number, lead name, builder display name). Move UUIDs into a collapsible "Technical IDs" section with copy buttons.
  - Use an `EntityCombobox` (type-ahead) for Lead (filtered to Won leads without an invoice) in Create invoice and for Builder in Issue key.
  - Give Estimates a recent-estimates DataTable with search, and keep ID lookup as one search mode.
  - Title disputes "Dispute on FEAS-2026-0105 · Elite Craft".

**M4. Replace the 11-link top bar with a grouped sidebar.**
- Screens: all desktop pages; `leads__mobile__loaded__menu-open-viewport.png`.
- Problem: 11 equal-weight links plus Sign out, with no active-state styling visible in any capture, no grouping, and no counts. "Billing" and "Invoices" are separate siblings, and nothing says Billing is a dashboard while Invoices is a ledger.
- Recommendation: the target IA below. Active item uses an `--accent-bg` fill plus a `--accent` left bar, and queue counts appear as badges (Disputes 2, Quarantine 2, Dunning 2).

**M5. Make mobile tables responsive.**
- Screenshots: B4–B6, plus `builders__mobile__loaded__manage-builder-modal-viewport.png`.
- Recommendation: below 768px, `AdminDataTable` switches to a stacked card list (primary cell as title, status chip on the right, 2–3 secondary fields, a row tap opens the drawer, actions live in the drawer footer). The Leads page already does a version of this; generalise it. Never let the page exceed the viewport: `min-width: 0` on grid children, `overflow-wrap: anywhere` for emails and keys.

**M6. One button system.**
- Problem: 5+ variants exist in the captures.
  - Dark brown filled (Add builder, Invite user).
  - Bright brass filled (Funnels "Apply").
  - Navy `#1f2937`-ish filled (Sheets "Sync now", Estimates "Look up"), which is off-palette.
  - Pale yellow outline (Billing "Review invoice", "Confirm retry").
  - Text-only "primary" (Users modal "Save changes", "Send invite").
  - Greyed-looking but enabled (Lead drawer "Apply Status / Apply Builder").
  - Native unstyled (API keys, Disputes, Calibration).
- Recommendation: an `AdminButton` with variants `primary` (`--canvas` bg, `--on-dark` text, or `--accent-deep`; pick one), `secondary` (card bg, `--border`), `ghost`, `danger` (`--danger`), `danger-secondary`. Sizes `sm` 32px and `md` 40px. One primary per view.

### Should-fix

**S1. One page shell and width.**
- Screenshots: `leads__desktop__loaded.png` (1104px cream card container), `disputes__desktop__loaded.png` and `billing__desktop__loaded.png` (no container, ~900–1100px), `funnels__desktop__loaded.png` (860px card with ~100px empty top padding), `ops-sheets__desktop__loaded.png` (~900px, right side empty), `calibration__desktop__loaded.png`.
- Recommendation: `AdminPage` gives a fluid content area beside the sidebar: `max-width: 1440px`, 32px gutter (16px on mobile), no nested cream card. Detail pages use a 2-column layout (main 2fr + side 1fr).

**S2. One type scale for admin.**
- Problem: H1 sizes vary. Funnels uses a marketing-size display H1 (~44px, tight tracking, Manrope-like). Disputes, Billing and Sheets use ~24px. Leads and Builders use ~28px.
- The tokens doc has only marketing sizes. Add admin tokens:
  - `--type-admin-h1: 24px/600`
  - `--type-admin-h2: 18px/600`
  - `--type-admin-body: 14px`
  - `--type-admin-meta: 12px`
  - `--type-admin-label: 11px uppercase .06em`
- All in `--font-ui`, per the tokens doc. Funnels must stop using `--font-headline`.

**S3. One date / number / money format.**
- Problem: three styles appear. "Nov 9, 2026, 11:30 a.m." (Disputes, Estimates), "Nov 13, 2026, 11:30:00 AM" with seconds (Billing, Invoice detail, Sheets), and ISO "2026-11-12" or full ISO-Z (Leads, Calibration, API keys). Counts are unformatted: "1843", "4820".
- Recommendation: `adminDate` (Nov 12, 2026), `adminDateTime` (Nov 12, 2026 · 11:30 a.m. MT), `adminRelative` ("2 days ago", full value on hover), `adminMoney`, `adminCount` (1,843), all built on `shared/utils/datetime.ts`, `edmonton.ts` and `money.ts`. Never show seconds.

**S4. Tokenise the status chips.**
- Problem: `_admin-lead-badges.scss` and each page hard-code their own hex pairs (321 hex literals across admin SCSS). The same status gets different colours: "Active" green differs between Builders, Users and API keys; "Invited" / "Quoting" amber differ; Calibration import status is plain text.
- Recommendation: add `--status-{neutral,info,success,warning,danger,accent}-{bg,fg}` to `styles.scss`, plus a `StatusChip` with a single status → tone map per domain (lead, invoice, user, builder, key, dispute, sync). Title-case labels come from one dictionary.

**S5. The Leads list is a card stack, not a table.**
- Screenshot: `leads__desktop__loaded.png` (2,563px tall for 18 leads, ~90px per row).
- Problems: unlabelled meta (Score 92 · embed · New build · elite-craft · 0-3mo · date), an unlabelled "In"/"Out" chip (contact consent), no sorting, no pagination, no bulk actions.
- Recommendation: `AdminDataTable` with columns Name/email · Address · Status · Builder · Source · Score (sortable) · Timeline · Created (sortable). Use 48px rows, label consent in a column header or tooltip, add saved views (New, Unassigned, Quoting > 7 days), multi-select for bulk assign and export, and 50 per page. Keep the stat cards as clickable filter tiles (they already work: `leads__desktop__loaded__status-filter-won-viewport.png`). Note that "Clear" sits beside the filter inputs, not next to the active filter.

**S6. Restructure the Lead drawer.**
- Screenshots: `leads__desktop__loaded__lead-detail-drawer-viewport.png`, `..._scrolled-viewport.png`.
- Problems: the Pipeline block has two separate "Apply" buttons that look disabled (low-contrast tan), and project type shows raw enum values (`new_build`, `standard`).
- Recommendation: one form with Status + Builder selects that save on change with optimistic UI and an undo toast, or one sticky footer "Save" that enables when dirty. Map enums through the label dictionary. Order the sections: Pipeline → Contact → Property & estimate (link to the estimate) → Invoices (link) → Notes → Record. Make notes a tab or keep them pinned at the bottom with the composer sticky.

**S7. Builders: drawer edit and a narrower table.**
- Screenshot: `builders__desktop__loaded.png`.
- Problems: builder names wrap to 4 lines, sign-in key code chips break mid-word ("bow-\nriver-\ncustom"), Plan and Default-method text wrap to 3 lines. The edit form exposes "Advanced settings (JSON)" as a raw textarea and uses native `<select>` elements that don't match the custom selects used elsewhere.
- Recommendation:
  - Table columns: Builder (name + slug in mono `white-space:nowrap`) · Status · Plan · Rate · Payment method (short label "Card auto", "E-transfer") · Leads (count, links to filtered leads) · Open invoices.
  - Edit opens in `AdminDetailDrawer` with sections Identity, Contact, Branding (with logo preview), Commercial, Embed origins.

**S8. Users: one modal, one save.**

- Problems: two independent save buttons in one modal ("Save changes" in the middle, "Save organizations" at the bottom), Cancel placed between sections, no X, and the title is jammed against the first label.
- Recommendation: a drawer with one form and one sticky footer [Cancel] [Save]. Move row actions into a kebab `RowActions` menu (Edit · Resend invite · Deactivate · Delete), since today 3 text buttons per row compete. Add search and a role filter.

**S9. Billing health: dashboard vs. work queue.**

- Problems: the page mixes KPI tiles, two work queues, webhook diagnostics and a create form toggled inline above the KPIs (`billing__desktop__loaded__create-invoice-form-viewport.png`, which pushes the page down). ## Proposed redesign

### Target IA (left sidebar, 240px, collapsible to a 64px icon rail; off-canvas sheet on mobile)

```
Feasly Admin                              [env chip: Stripe test]  [user menu ▾]
─ Pipeline
   Leads                 (badge: New count)
   Quarantine            (badge: count)        ← promoted from a tab
   Estimates
─ Partners
   Builders
   Users & access
   API keys
─ Money
   Billing overview      (KPIs + queues)
   Invoices              (ledger)
   Disputes              (badge: open; red if breached)
─ System
   Calibration
   Sheets sync           (dot: health)
   Funnels
   Webhooks              ← split out of Billing
```

- Global **Command / search** (⌘K): type a lead name, email, invoice number or builder slug and jump to its drawer. This replaces "paste a UUID" everywhere.
- **URL-addressable drawers**: `/admin/leads?open=<id>`, `/admin/invoices/FEAS-2026-0105`, `/admin/disputes/<id>`. Back closes the drawer, and links can be shared.
- **Cross-link chain**: Lead drawer → Builder link + Invoices list → Invoice drawer → Dispute link → Dispute drawer → back to Invoice/Lead. Every entity reference is an `EntityLink`.
- User menu holds Sign out and the signed-in identity. Remove Sign out from the nav row.

### Admin component kit (`apps/web/src/app/features/admin/kit/`, or `shared/admin-ui/`)

All components use `--font-ui`, palette tokens, and new `--status-*`, `--type-admin-*` and spacing tokens (`--space-1…8` = 4/8/12/16/24/32/48/64). They are built on Angular CDK (Overlay, A11y FocusTrap, Table) to get focus management and keyboard handling.

| Component | Spec |
|---|---|
| **AdminShell** | Sidebar (240 / 64 collapsed, persisted in localStorage) + top bar 56px (breadcrumbs, ⌘K search, env chip, user menu) + `<main>` fluid, max 1440px, padding 32px desktop / 16px mobile. Below 1024px the sidebar becomes an off-canvas sheet (focus-trapped, Esc closes). Has its own error boundary: admin errors render inside the shell, not on public `/error`. |
| **AdminPageHeader** | Breadcrumbs (optional) · H1 `--type-admin-h1` · one-line description (muted 14px, max 72ch; long explanations go behind an info tooltip) · right-aligned actions (1 primary + up to 2 secondary + overflow kebab). On mobile, actions wrap under the title, and the primary goes full-width only when it's the sole action. |
